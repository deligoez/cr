# cr v0.3.0 — The experiment is scoped, and the round is not repeated

> The release notes for the `v0.3.0` tag.

v0.3.0 is the first release since v0.2.0 to change the contract: `spec/0.3.0.md` replaces `spec/0.2.0.md`
as the normative document, and the diff between them is 356 lines. Everything in it comes from the first
field trial of cr on a real pull request — 106 units, 424 prompts, 42 records — or from the data-safety
incident that trial exposed. v0.2.2 and v0.2.3 answered what could be answered without normative text;
this release takes the rest, and the record of what was reported, verified and decided stays in
`spec/field-feedback.md`.

The re-review half of the loop — anchor migration, recheck, resolving threads — is v0.4.

## Install

```bash
brew install deligoez/tap/cr
go install github.com/deligoez/cr/cmd/cr@v0.3.0
```

Run `cr init` after upgrading: it updates the profiles and the ejected role files you never edited.

## The experiment is scoped to what it speaks about

- **A probe runs one baseline, over its own population.** §5.2.2 previously required an unfiltered
  whole-suite run before any probe, so a filtered probe ran every test in the repository as a side effect —
  ten minutes of the field trial, against the wrong database. A probe's baseline is now the same filter and
  the same paths, unmutated, recorded once per head, sandbox generation, filter and paths. §5.2.5 is
  unchanged: a baseline that selects no test does not pass, so nothing is supported on an empty run.
- **`cr test` and `cr probe run` take a repeatable `--path`.** A profile carries `tests.paths_arg`, the
  template that puts a path on the runner's command line. A path must be relative, clean and resolve inside
  the sandbox, or the command exits 2; whether it exists is the runner's to answer. A `--path` given to a
  profile without `tests.paths_arg` exits 3.
- **A gap probe's baseline is the tests beside the one it injects.** It is the run with the probe's `--path`
  values and no filter — the whole suite when none are given — and at least one path must lie under the
  directory the probe's file is placed in, or the command exits 2. That is what keeps the environment check
  honest: the injected test's failure can only be attributed when tests of its own kind just passed.
- **Run records carry `paths` beside `sandbox`**, and the evidence region of a posted comment names the
  filter and every path, so a reader can see exactly which tests the claim rests on.

## The sandbox says what it requires

- **`sandbox.require`** names the paths that must exist inside the sandbox. When one is missing, `cr test`
  and `cr probe run` refuse with exit 3, naming the path and `sandbox.copy`. Both shipped profiles require
  nothing: a repository whose tests need no file on disk is not inconvenienced.
- **§5.1.2 now requires the report v0.2.2 shipped**: every gitignored file at the repository root matching
  `.env*` that the sandbox did not receive is named. The sandbox must hold every `sandbox.copy` entry the
  checkout holds, with the same content for regular files, except the entries the setup itself changed or
  removed — and those exceptions are now written into §5.1.6 rather than left to the implementation.
- **A sandbox or a run record from before generations is not reused.** A post-setup baseline that records no
  generation is not clean, and a run record carrying no sandbox matches none, so the first probe after the
  upgrade measures a fresh baseline instead of trusting an older one.

## A round is not judged twice

- **`cr review` emits only what the round still owes.** A cell the round already holds at its head is not
  re-emitted; a cell whose prompt predates a standing note on its claim or unit is. `--all` restores the full
  fan-out. `expected_cells` still lists every cell, now with `recorded` and `stale_by_note`. In the field
  trial the second fan-out re-emitted all 424 prompts, including the 106 intent cells already recorded.
- **`cr review --units <ids>` and `--shard k/n`** narrow a fan-out. The shard partition is contiguous over
  the units in id order, so k of n covers every unit exactly once; an unknown unit exits 1, a malformed
  shard or both flags together exits 2.
- **The record schema is written once per round.** `cr review` writes `rounds/<n>/contract.md` and every
  prompt names it, instead of repeating the §6.1 table. Each prompt still states its own output path, its id
  block and the fields an agent may not write — the two things that make a bad record refusable.
- **A role file may declare a class vocabulary.** Prompts print it, and `cr record` reports a class outside
  it without ever refusing: 42 records in the trial carried 36 distinct classes, which leaves triage
  statistics with nothing to group.

## Triage without line arithmetic

`cr triage <pr> <record-id> not-here|wrong|soften|keep [--body-file <f>|-]` makes the edit a hand edit would
make, under the per-PR lock: it deletes the block, sets the marker, or replaces the agent's region of the
body. The field trial's triage was done by deleting 20 blocks and replacing 20 bodies in a 62,000-character
file by hand, and one range overshot. Refusals: an unknown or already-deleted record exits 1, `soften` on a
record that is already a question exits 1, `--body-file` with `not-here` or `wrong` exits 2, and a moved head
refuses exactly as `cr draft` does. §8.1.2 now names `--body-file` as the draft's other input path, so the
invariant that a body reaches GitHub only through the draft still holds and is still checkable.

One consequence worth knowing: in a round where §6.3 already forced every `argued` record to a question,
`soften` has nothing left to do, and `keep --body-file` is the verb an agent wants.

§8.1.3's reserved sequence is also enforced where it can be enforced exactly. `cr triage --body-file` refuses
a body containing `<!-- cr:` with exit 1, naming the record, before `draft.md` is touched; `cr draft` and
`cr post` refuse a block whose body brought a second label, provenance or evidence region. Before this
release such a body was swallowed and the text inside the forged region discarded at exit 0.

## The issue is more than the tracker's text

- **`--intent-extra <path>` is repeatable** on `cr brief` and `cr claims record`, and `intent.extra_files`
  does the same from configuration. The issue text becomes the tracker's text followed by each extra file
  under a separator line naming it. A rule that lives in a linked document can now become a claim.
- **A claim drawn from such a file carries `source: file` and names the file**, and its span must lie wholly
  inside that file's part: a span may never contain or cross a separator. A comment resting on it discloses
  the document to the reader, because a claim from a linked file rests on weaker ground than the tracker's
  own text.

## Housekeeping the contract now covers

- `cr init` replaces an ejected role file nobody edited, exactly as it replaces a profile; every command that
  loads the corpus names a role file an earlier release shipped, and `cr init` is named as the fix.
- §2.3's table lists `emissions.ndjson`, `issue.json`, `sandbox-baseline.json`, `rounds/<n>/intake.json` and
  `rounds/<n>/contract.md`. cr now refuses to write any file under a pull request's state directory that the
  table does not name, and a test walks a fully populated tree to prove the two agree.

## Known limitations

- Probes still run the pull request's test command on the reviewer's machine. Isolation for code from outside
  the team is not in this release.
- `cr review`'s narrowing is the only volume control; a large pull request still emits hundreds of prompts.
- A baseline is keyed by the paths as they were given, in order, so the same two paths in the other order
  measure a second baseline. Neither shipped profile sets `tests.paths_arg`, so `--path` needs a profile that
  says how the runner takes a path.
- The re-review half of the loop is v0.4: a moved head still makes the round stale and `cr brief` opens a new
  one, with no anchor migration.
- The limitations listed in the v0.2.1, v0.2.2 and v0.2.3 notes still apply.

## Verification

- **Quality gate on a clean clone of the tag's tree**, under Go 1.26.5 and Go 1.27.1 with the tools installed
  by Go 1.27.1: `go test -race -count=1 ./...`, `golangci-lint run`, `scripts/deadcode.sh`, `gofmt -l`, and the
  suite repeated twice more. All green.
- **Four QA passes over local fixtures**, each in its own `CR_HOME`, with `~/.cr` hashed before and after, a
  `gh` shim that refuses every write, and no tracker: 161 checks over the clauses above and their negative
  directions — what must still be refused, what must not be emitted, what must not change.
  - The fan-out: the narrowing and `--all`; the three note-link rules each against a retracted note, an older
    note and a note on another unit; `--shard` partitions checked against §4.6.1's formula for eight values of
    n over a 62-unit pull request; nine malformed shards; the contract file named by all 248 prompts of one
    round.
  - Triage: every verb against the equivalent hand edit, byte-identical in `draft.md` and in everything the
    next `cr draft` and a dry `cr post` produce; every refusal; 24 parallel pairs losing no edit.
  - Intent: every span corner against the separator rule, drift over the joined text, and the provenance a
    file-sourced claim discloses.
  - Sandbox and probes: the scoped baseline proved from the runner log against a whole suite that was failing
    and was never run; a zero-selection baseline leaving a record `argued`; the gap-probe path rule;
    `sandbox.require`'s refusal; the generation checks.
- **Five defects found and fixed**, each with a regression test that drives the command: a forged `cr:` region
  in a body was stripped instead of refused, and four documentation statements did not match the binary.
- Nothing ran against the repository of the field trial; every fixture is local.

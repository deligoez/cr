# cr v0.2.3 — What the first field trial asked for

> The release notes for the `v0.2.3` tag.

v0.2.3 implements `spec/0.2.0.md` unchanged: a patch release carries no normative change. It answers the
first review of a real pull request with cr — 106 units, 424 prompts, 42 records, 20 comments kept — by
the operator who ran it. Every item was verified against the code and the stored state before it was
built, and five suggestions were declined because they would have had cr form a judgement or raise the
cost of a wrong comment; each of those has an alternative here instead. The record of what was reported,
what held and what was decided is in `spec/field-feedback.md`.

It also carries v0.2.2's sandbox repair, so a sandbox whose setup deletes a copied file is no longer
rebuilt before every run.

## Install

```bash
brew install deligoez/tap/cr
go install github.com/deligoez/cr/cmd/cr@v0.2.3
```

## What a round now tells you

- **Notes recorded after the prompts went out are reported.** `cr review` writes one line per emitted
  prompt to a new `emissions.ndjson` (round, head, pass, unit, role, time, the note ids it carried).
  `cr note` then names the passes it postdates and the command that re-emits them; `cr record`,
  `cr status` and the draft header report the records written from a prompt older than a note on their
  claim or unit, under `notes_after_prompts`. Nothing is refused and nothing is stored on a record: the
  report is computed when it is read. A retracted note stops being reported.
- **Cells the round already holds are marked.** `expected_cells` entries carry `recorded: true` for a cell
  recorded at the round's head, and a terminal prints `(recorded)`. Every prompt is still emitted; the
  skill says to run only the unrecorded ones after `cr map record`, with the `jq` filter to select them.
- **Sub-agents are batched.** The skill no longer says one sub-agent per prompt, which is not feasible at
  424 prompts. It gives a size guide from the field trial's own numbers: 106 intent prompts across 8
  sub-agents, and 318 other prompts across 8.
- **A probe that established nothing says why.** When a probe's baseline did not pass, `honesty` names the
  baseline run and its failed count, so a record is not left looking merely unlucky.
- **Possible duplicates are listed for the human.** `cr merge`'s report pairs merged records that share a
  citation, or where one cites a line inside the other's anchor, naming the link. Nothing is dropped and
  no record gains a field: the field trial's four cross-unit duplicates of one root cause were invisible
  to dedup, which keys on path, side, line and class.

## What the issue text now yields

- **Transport noise is cleaned at ingestion.** Terminal control sequences and no-break spaces are removed
  from the issue text before it is stored, so a span copied from `cr brief`'s printed text records. Line
  breaks stay significant. Rounds recorded before this release report no false drift.
- **Links are disclosed.** `cr brief` lists every URL the issue text carries, including one carried only as
  a terminal hyperlink's target, as a document cr did not read. A rule that lives only behind a link can
  never become a claim, and now the report says so.
- **Uncovered paragraphs are listed.** `cr brief` and `cr status` list the issue paragraphs no claim span
  covers, without ranking them. In the field trial an intent record asserted the issue stated no counting
  window, while the issue text did: claim extraction had skipped it.

## What the draft now says

- **A question body without a "?" is named before posting.** `cr draft` warns over rendered or kept
  question bodies that do not ask, with the ids and a count in the header; `cr post` keeps its refusal.
  Every prompt's output contract states the rule.
- **Long bodies are counted.** The draft header names bodies over 1,200 characters. The posted body is the
  agent's rewrite, and the first draft's is evidence prose, 858 characters at the median in the trial.
- **The `wrong` waiver's moment is disclosed.** The header says a record marked `wrong` writes a
  repository-wide waiver when the draft regenerates — before any post, which is where the skill implied
  it happened.
- **The skill says to write the reader-facing prose in `render.lang`.** Records are stored in English and
  the agent rewrites the bodies at draft time; no prompt had said so.

## What the roles now ask for

- **A missing test is raised where a probe can support it.** Test adequacy is a property of the code under
  test, so the test-adequacy role raises "this production line has no test" from the production unit's
  cell, anchored on that line and citing the test file. Raised from the test file's own unit, the probe's
  target can never lie inside the record's anchor, and 7 of the trial's 19 probes supported nothing for
  that reason.
- **A shared predicate's other occurrences go in the evidence, not the citations.** The correctness role
  searches for the other places a predicate or rule appears and names them in the evidence, saying which
  it checked. A citation stays what a reader opens to see the premise of the defect; another copy of the
  same code is not one, and treating it as one would move reading-only findings into the assertion
  register. Measured over six of the trial's correctness prompts: the grade did not move, copy citations
  fell from 3 to 0, and every finding in the sample was a real defect.

## Kept as it was, after measuring

- **Rename similarity stays at 50%.** A module move left LEFT units for the originals and RIGHT units for
  the destinations. 30% pairs those moves, and it also pairs unrelated files that share boilerplate — a
  deleted Go test with an unrelated added one at 31%, an Invoice model with an unrelated Customer model at
  46%, inside the same range as the real moves. A false pair puts a deleted file's lines in a unit on
  another path, where no anchor can land. The skill instead says a moved, unchanged unit is a `pass` cell.

## Known limitations

- A role file ejected by an earlier release keeps that release's instructions. The skill now names exactly
  which paragraphs changed and how to diff an ejected file against a fresh `cr init --eject-roles`.
- A filtered probe still runs the whole suite once per head as its baseline. A baseline scoped to the
  probe's filter is v0.3.0.
- The limitations listed in the v0.2.1 and v0.2.2 notes still apply.

## Verification

- **Quality gate on a clean clone of the tag's tree**, under Go 1.26.5 and Go 1.27.1 with the tools
  installed by Go 1.27.1: `go test -race -count=1 ./...`, `golangci-lint run`, `scripts/deadcode.sh`,
  `gofmt -l`, and the suite repeated twice more. All green.
- **Two QA passes over a local fixture**, each in its own `CR_HOME`, with `~/.cr` hashed before and after
  and a `gh` shim that refuses every write: 94 checks over the items above and their negative directions —
  what must still be refused, what must not be reported, and what must not change. 84 passed; 4 failed,
  from three defects, each fixed here with a regression test that drives the command; the remaining checks
  recorded behaviour the contract does not fix.
- Nothing ran against the repository of the field trial; the fixture is local and the backend repository
  was read only.

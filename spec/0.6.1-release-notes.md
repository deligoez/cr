# cr v0.6.1 — A moved anchor reads as moved

> The release notes for the `v0.6.1` tag.

After v0.6.0 shipped, a QA pass drove every command against real pull requests on GitHub: a PHP
scratch QA repository and a new Go QA repository for the `go` profile. It found
two defects, and v0.6.1 is those two fixes and nothing else. The contract is still
`spec/0.6.0.md`; neither fix changes a word of it, because in both cases the spec already said what
v0.6.1 now does.

## Install

```bash
brew install deligoez/tap/cr
go install github.com/deligoez/cr/cmd/cr@v0.6.1
```

## `cr recheck` reported code that had moved as unmoved

**This one told the reader something false, so it comes first.** When the author pushes, `cr
recheck` migrates the anchors of the records cr holds (§9.4) and reports where each one landed.
v0.6.0 read the file at the head the round was opened at, which is the commit the record's anchor
was taken from, so every anchor was found exactly where it had been. On the scratch QA repository, three
lines inserted above a queued record were reported as `33 → 33`: nothing moved. The code had moved
three lines.

§9.4.2 says a migration reads the current head's tree, and it now does.
`TestAMigrationReadsTheHeadThePushMovedTo` makes a real second commit that inserts three lines,
briefs over it, and expects the anchor at `lib.go:4` to be reported at `lib.go:7`; run against
v0.6.0's `recheck.go`, it reports `lib.go:4`.

No comment reached an author through this. The records it misreported were unsent ones, and the
brief that follows a push stales every unsent record before it can be drafted or posted. But a
reviewer who read v0.6.0's recheck output was told the code under a concern had not changed when it
had.

## A Go gap probe at the repository root came back `inconclusive`

v0.4.1 let `tests.probe_path_template` open with `<target-dir>`, so a Go gap probe's test is placed
in the package it tests and its run is scoped to that directory. A package at the repository root
has the directory `.`, and v0.6.0 treated that as no directory at all: it handed the placed file
itself to `go test`, which compiled the file alone as `command-line-arguments`, failed on the
undefined function it was meant to test, and left every such probe `inconclusive`. That is
measurement 4's symptom again, one directory up. It was found on the Go QA repository, whose package
sits at the root, as most small Go modules' do.

§5.4.2 makes no exception for the root, and `go test ./.` runs the root package. The probe's run now
names `.` like any other directory.

## Not in this release

The same QA pass found seven more items. None of them lets a wrong assertion reach an author, and
all are in `ROADMAP.md`:

- a spec question, in §0: §9.4 migrates exactly the unsent records §9.3.4 stales on the next brief,
  so a migration currently persists nothing, and two ways to settle it are waiting for a decision;
- five small items, in §1: `cr test --json` shows no counts, a pull request with no history in
  common with its base fails on a raw git error, `cr config --resolved` shows the Jira key pattern
  under the GitHub tracker, a pull request closing two issues needs `--issue` with no candidates
  named, and GitHub can report the old head for a few seconds after a push (the skill now says to
  brief again);
- a measurement gap, in §2: `cr post --reconcile` has not yet run against a real unknown outcome.

## Upgrading

Nothing to do. No state format changed and no command gained or lost a flag.

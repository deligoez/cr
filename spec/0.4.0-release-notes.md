# cr v0.4.0 — The experiment a role can ask for

> The release notes for the `v0.4.0` tag.

v0.4.0 implements `spec/0.4.0.md`, whose one new obligation is §5.7: a role that holds a suspicion it
cannot establish may propose the experiment that would settle it, and running that proposal is what
re-grades the record. Everything else in the contract is v0.3.0's, with its self-references moved to v0.4
and its forward references to v0.5.

It also carries the three fixes of the v0.3.2 that was never tagged. They are described under **Also
fixed**, and the credential fence among them is the one to read first.

## Install

```bash
brew install deligoez/tap/cr
go install github.com/deligoez/cr/cmd/cr@v0.4.0
```

## A role can ask for an experiment

§5's probes are what separates cr from a reviewer that only reads, and until now the fan-out gave a role no
way to reach them. §6.1 offers a record one field for an experiment, `probe`, and it holds the id of an
experiment that **already ran**. A role that had found something it could not establish had nowhere to put
the experiment that would settle it.

What that cost is measured. Against a careful human reviewer on a real pull request, cr produced 51 records:

| grade | count |
|---|---|
| cited | 32 |
| argued | 19 |
| **probed** | **0** |

Zero. Both measurements needed a hand-built side channel before a single probe could run, and 25 records
across them wrote prose into the one field cr has decided never to read.

**A proposal is now data of the same kind as a claim.** A role writes it to the second path its prompt
names, with the `x<n>` ids that prompt gave it; `cr proposals record` validates and stores it; `cr probe
run --proposal <id>` executes it.

```bash
cr proposals record 1 proposals.ndjson
cr probe run 1 --proposal x101
```

A proposal carries `kind` (`mutation` or `gap`), `role`, `unit`, `target`, `hypothesis`, `settles`,
`input` — the unified diff or the test file's content — and optionally `finding`, `filter` and `paths`. It
is machine-checkable the way a claim is: §5.7.1 refuses a computed field, a field of no row, an id outside
the block §4.6.2 gave the prompt, a repeated id, a kind outside the two, a unit of no round, an inactive
role, a target that does not resolve at the head or lies outside its own unit, a finding naming no record,
and an empty required string. It stores nothing when it refuses.

**A proposal is never evidence, and that is structural.** `probe` stays the id of an experiment that ran;
a record naming a proposal there is refused. The package exposes nothing a grader can ask, so §5.7.2 is
something cr cannot do rather than something it refrains from doing. Only running the proposal produces
the probe record that grades.

**Running it is what changes the register.** The proposal becomes `run` carrying its probe, and the record
it named gets that probe, a recomputed grade, and §6.3's forcing again. The command reports the grade the
record held and the grade it holds.

That recomputation is the **one exception to §6.2's ratchet**, and the narrowness is the argument. The
ratchet refuses a raise that happens behind the reviewer, because a human who approved a question must not
post an assertion. This raise happens because somebody spent an experiment on purpose. It posts nothing by
itself either: §7.2's table still requires the human's own edit in the draft to turn the record into a
finding, so the assertion still has an author.

**Nothing is hidden and nothing is blocked.** A proposal cr cannot run — no `tests.cmd`, or a gap proposal
under a profile with no probe path template — is stored `unrunnable` with the reason rather than dropped.
An open proposal never makes a round incomplete: cr cannot establish that an experiment was worth running,
and refusing to finish a round over one would make the reviewer's judgement cr's. `cr status` counts them
by state, names the open ones, and says so when the round has asked for more experiments than
`probe.max_per_round` still allows.

## Also fixed

**A credential-shaped file is listed, not clustered.** Measured at v0.3.1: a tracked `.env` in a pull
request's diff was matched by no glob, was not binary and was not generated, so it was clustered and its
added lines reached every role's prompt verbatim. Such a file is now a third listed kind beside §3.4.7's
`binary` and `generated`. It is named by path and its content reaches no prompt. The fence is read
**before** `ignore.globs` and is not a setting: §2.7's layers replace a list value outright, so a default
glob would disappear the moment a repository set that key. Matched case-insensitively on the base name:
`.env` and any `.env.*`, `.netrc`, `.pgpass`, `.htpasswd`, `credentials`, `secrets`, the `id_rsa` family
with or without `.pub`, and the extensions `.pem`, `.key`, `.p12`, `.pfx`, `.keystore`, `.jks`.

**A process of the test runner that outlives the run is disclosed.** v0.3.1 bounded the wait after
§5.2.3's kill; the survivor was still neither killed nor reported. Every process the runner starts
inherits the runner lock, so once cr closes its own hold the lock is held by exactly the processes of that
run still alive. When it is still held two seconds later, `cr test` and `cr probe run` say so. The notice
states only what was observed: which process holds it, and whether it left the group, is not something cr
can establish.

**The `laravel-pest` profile ships four house-style rules.** Measurement 3's evidence: seven of the eight
comments cr missed against a careful human reviewer were shaping comments, which are neither in the issue
nor in the diff. The four are a negative test named `it_does_not_...`, a local read once, a variable named
for where a value came from, and fixture setup repeated across tests. They ride in the profile's `rules`
array, which §2.6 item 1 already names as the third layer, and **every one keeps the default `question`
register**: a team that never adopted them did not declare them, and an assertion of house style cr
invented is the wrong comment this project spends its trust on.

## Also

- The stale-profile notice no longer claims that `cr init` will leave the sandbox short of a file it
  copies unless `sandbox.copy` is one of the fields that actually moved.
- `internal/profile/builtin/shipped/` gains the `laravel-pest` bytes of v0.2.2, v0.2.3, v0.3.0 and v0.3.1.
- Go 1.27's modernizers applied across the tree.

## Not in this release

- The re-review half of the loop. `cr recheck`, `cr verify`, `cr resolve` and `cr accept`, anchor
  migration included, are v0.5, declared out of scope in §1.3.6.
- The normative clause for the credential kind. §3.4.7 names two kinds without closing the set, so listing
  a third contradicts no MUST; the clause is owed to the next spec revision.

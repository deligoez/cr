# cr v0.3.1 — What cr found when it reviewed itself

> The release notes for the `v0.3.1` tag.

v0.3.1 implements `spec/0.3.0.md` unchanged: a patch release carries no normative change. Every fix here
was found by measurement 1 (`spec/measurements/2026-09-18-m1-recall-against-known-defects.md`), which ran
cr's own reading roles over cr's own v0.1.0 packages as a pull request. The roles found none of the 24
known defects the measurement was built around, and instead said six true things about cr that the
recorded audit rounds had passed; each of those, verified by reading and then by execution, is a fix
below. The record is `spec/field-feedback.md`, section M-1.

## Install

```bash
brew install deligoez/tap/cr
go install github.com/deligoez/cr/cmd/cr@v0.3.1
```

## Fixes

- **A record quoting cr's own marker sequence is refused where it enters, not where it is drafted.** A
  role reviewing cr's draft grammar quoted `<!-- cr:` in its evidence; `cr draft` refused the record under
  §8.1.3 and pointed at a draft that did not exist, and no command could ever render it. `cr record` and
  `cr merge` now refuse a record whose `summary`, `evidence` or `suggestion` carries the sequence, with
  exit 1 naming the file, the line, the record id and the field, and a hint telling the role to rewrite
  its text; nothing is stored. A record stored by an earlier release is still refused at draft time, and
  that hint now says so and names the file holding it. (M-1.1)
- **The issue-key rewrite refusal offers only the remedy that works.** `cr brief` refuses a run whose
  resolved key differs from the recorded one and used to offer `--issue <recorded>` in every case; when
  `intent.key_pattern` has changed so the recorded key no longer matches it, that flag runs through the
  same pattern and the refusal recurs — the 14 recorded audit rounds had passed those lines. The message
  now says the pattern no longer admits the recorded key and offers restoring such a pattern or removing
  the pull request's state directory; `--issue` is offered only while the pattern admits the key. (M-1.2)
- **A corrupt `rounds/<n>/rendered.json` exits 3 with the stored-state hint.** It exited 2 with "check the
  command line", the class the v0.2.0 QA had fixed for meta.json only. (M-1.3)
- **A sandbox directory that is no longer a readable worktree is rebuilt.** §5.1.6's check returned git's
  error instead of an unclean reason, so the sandbox was never recreated; and the removal git itself
  refused ("validation failed, cannot remove working tree") is now done as cr's own files under `~/.cr`
  followed by a prune. The recreation is reported with its reason. (M-1.4)
- **A copy into the sandbox never writes through a symbolic link the head checked out.** Measured: with
  the head tracking `.env -> <a file outside both trees>` and `.env` in `sandbox.copy`, the copy wrote the
  checkout's `.env` into that outside file. Every write of the copy now goes through an `os.Root` opened
  on the sandbox, a link at the target or in its path is replaced by the regular file the checkout holds,
  and a link the copy itself reproduces (a `vendor` tree full of them) is still created. (M-1.5)
- **A test run whose survivor left the process group no longer blocks forever.** After the timeout kill,
  `cmd.Wait` waited for a descendant outside the group that held the output pipe; measured, a 500 ms
  budget did not return in 15 s. `WaitDelay` bounds the drain at 2 s and the run reports the runner's own
  exit status as timed out. The survivor is not killed — cr cannot signal a process outside the group —
  and is not yet reported; that disclosure is a candidate. (M-1.6)

## Also

- The `KeyRewriteError` hint in `exit.go` names both remedies.
- `skills/cr/SKILL.md` says `cr record` and `cr merge` refuse the reserved sequence.
- `golangci-lint` v2.13.2 on the developer machine had been installed by Go 1.26.5 and failed on Go
  1.27.1's standard library; reinstalled with `GOTOOLCHAIN=go1.27.1`, as CLAUDE.md prescribes.

## Not in this release

- A disclosure for a runner's survivor outside the process group (M-1.6's remainder).
- `--issue` exempt from `intent.key_pattern` when it names the recorded key (a normative change; v0.4
  candidate).

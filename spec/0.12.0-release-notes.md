# cr v0.12.0 — A probe re-run is asked for, not implied

> The release notes for the `v0.12.0` tag.

v0.12.0 implements §9.5.4, which no release had: a posted record's probe checked again at the head
the author pushed. The contract is `spec/0.12.0.md`, and it changes §5.5 and §9.5.4 alone.

## Install

```bash
brew install deligoez/tap/cr
go install github.com/deligoez/cr/cmd/cr@v0.12.0
```

## `cr probe run --rerun` repeats a stored probe

`cr probe run <pr> --rerun <probe-id>` executes the stored probe's kind, input, filter, paths and,
for a gap probe, its target at the current round's head, as if they had been given on the command
line, and writes a new probe record whose computed `rerun_of` names the probe it re-ran. The probe
is found in any round of the pull request, so a record posted in round 1 has its probe re-run in the
round the push opened.

Every input flag beside `--rerun` — `--proposal`, `--kind`, `--patch`, `--test`, `--target`,
`--filter`, `--path` — exits 2 before anything runs, and an id naming no probe of the pull request
exits 1. A re-run changes no record's `probe` and no grade: what its result establishes is still
§5.3.5's and §5.4.4's, and whether the concern was addressed is still the agent's to record with
`cr verify`.

## `cr recheck` reports the re-run, and runs nothing

§9.5.4 used to have `cr recheck` re-run the probe itself. It never did, and v0.11 said so in an
honesty line. The execution now belongs to the command that already says it executes: `cr recheck`
is what a reviewer runs believing it only reads, and on a real repository a suite run can reach a
local database.

For every posted record naming a probe, `cr recheck` reports the latest probe at the round's head
whose `rerun_of` names it, with its `result` and `reason`, or that none has run — with the exact
command that performs one:

```json
"rerun": {"of": "p1", "head": "0f1e2d3", "ran": false,
          "command": "cr probe run 42 --repo acme/web --rerun p1"}
```

A re-run recorded at an earlier head is not that answer, so the command is named until one runs
at this one.

## Upgrading

Nothing to do. Probe records written before v0.12 carry no `rerun_of` and read as probes that
re-ran nothing, which they are.

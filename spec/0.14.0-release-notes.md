# cr v0.14.0 — What the first live tester found

> The release notes for the `v0.14.0` tag.

A separate agent ran cr 0.13.0 on a real pull request, `tarfin-labs/backend#6328`, and reported as it
went. v0.14.0 is what that report asked for, and the contract is `spec/0.14.0.md`.

## Install

```bash
brew install deligoez/tap/cr
go install github.com/deligoez/cr/cmd/cr@v0.14.0
```

## A cell that cites a note is not made stale by it (§4.6.1)

§4.1.5 has the agent record a note that explains an unmapped unit and cite it in the cell's
`note_id`. On #6328 the note was linked to no claim, so it sat on every unit, and after the cell was
re-recorded citing it, bare `cr review` re-emitted all thirteen intent prompts, the cited one
included. A held cell is no longer made stale by the note it cites; the other cells still are.

## The issue's own link is not listed as unread (§3.1.7)

jira-cli prints `View this issue on Jira: https://…/browse/WB-3295` under every issue, and the brief
listed it as a document cr did not read. A link whose last path segment is the issue key, in any
letter case and with a trailing slash trimmed, is no longer listed.

## The test runner does not see a coding agent (§5.2.1)

Under Claude Code, which sets `AI_AGENT`, Pest 4 printed
`{"tool":"pest","result":"passed","tests":21,…}` in place of its recap, so rounds 1 and 2 read
`tests_run` null and `passed: false` over an exit of 0; round 3, with `AI_AGENT` unset, read 21 run,
0 failed, and passed. cr now starts the runner without the variables coding-agent detectors read,
the union of `laravel/agent-detector` and `ergebnis/agent-detector` (`AI_AGENT`, `CLAUDECODE`,
`CODEX_SANDBOX`, `CURSOR_AGENT`, `GEMINI_CLI` and the rest, listed in `internal/sandbox`). A run that
still exits 0 with no executed count is disclosed under `honesty` by `cr test` and `cr probe run`:
such a run cannot pass or serve as a baseline. `cr test`'s document now carries the run's
`output_tail` as well, which `--compact` omits.

## A prompt names where its coverage cell goes (§4.6.2)

Every prompt names `fanout/<round>/<unit>/cells-<role>.ndjson` beside the role's records and
proposals, and `rounds/<n>/contract.md` carries §4.5.5's cell schema: `unit`, `role`, `result`,
`reason`, `coverage` and `note_id`, with `unit_hash`, `head` and `round` cr's own. A test-adequacy
prompt now also says the role cannot run tests, that a §5.7 proposal is its only experiment, and
what a classification means on a unit that is itself a test file.

## Probes and proposals (§2.4.5, §5.1.2, §5.7.3, §5.7.5)

- `laravel-pest` sets `tests.paths_arg: ["{path}"]`, so `--path` reaches Pest as a bare argument;
  `./vendor/bin/pest tests/Machines/CarSales` ran 336 tests. The profile's bytes changed, so a
  `laravel-pest.json` an earlier release wrote is named stale and `cr init` updates it.
- A proposal carrying `paths` under a profile with no `tests.paths_arg` is stored `unrunnable` when
  it is recorded, with a reason naming the field, rather than stored open and refused by
  `cr probe run --proposal` with exit 3.
- A proposal already run whose probe's result is `inconclusive`, `error` or `timeout` runs again,
  and the proposal and the record it names move to the new probe. On #6328, `x4001` ran
  inconclusive under the agent-detecting runner and could not be run again. Any other result is
  still refused with exit 4.
- A gitignored `storage/*.key` the sandbox lacks is reported like a root `.env*` file: without
  Laravel Passport's keys, 19 baseline tests failed `Invalid key supplied`.

## The evidence region (§8.1.7)

A probe whose result is `no-test-failed` or `passed` shows, in place of its output tail, the lines
`tests.count_pattern` matches; a probed comment on #6328 carried sixty lines of passing tests.
Every record naming a probe, a question included, now carries each re-run of that probe at the
round's head with its result: a question a re-run had refuted by experiment reached the draft with
nothing saying so.

## The review body is written in `render.lang` (§8.1.1, §8.4.3)

`render.lang` defaults to `en`. The review body's framing lines and axis names are built in per
language, as the question labels are, and each lens's reason keeps its wording; through v0.13.0 the
body was English under every language, the one English text a Turkish team's author received.

## Upgrading

A team that relied on the old `tr` default sets it in its repository's configuration,
`~/.cr/repos/<owner>/<repo>/config.json`:

```json
{"render": {"lang": "tr"}}
```

A `laravel-pest.json` profile an earlier release wrote, unedited, is reported stale by every
command that loads it; `cr init` updates it to gain `tests.paths_arg`.

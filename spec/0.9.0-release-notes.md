# cr v0.9.0 — Jest, and a zero read only from a clean exit

v0.8's `typescript` profile runs Vitest, so a React or React Native project whose
runner is Jest read every test run as undetermined. v0.9 ships a `jest` profile,
and fixes the two things building it exposed. The contract is
[`spec/0.9.0.md`](0.9.0.md); only §2.4.5 and §5.2.1 changed.

## `jest`

- Selected by Jest's own configuration files: `jest.config.{js,ts,mjs,cjs,json}`
  and `jest.setup.{js,ts}`.
- Runs the repository's own Jest: `npx --no -- jest --json`.
- Sums `numPassedTests` and `numFailedTests` from the JSON report, because Jest
  prints no line per test to count. A skipped or todo test is not counted.
- `--filter` becomes `-t`, `--path` is passed as Jest's path pattern, and a gap
  probe's test is placed beside its target as `cr_probe_<id>.test.js`.
- Indexes the same files as `typescript`, with the same scanner.

A project that configures Jest only inside `package.json` selects no Jest file
marker; name the profile with `"profile": "jest"` in the per-repository config.

## No profile selects on `package.json`

Every JavaScript repository has a `package.json`, so a second JavaScript profile
that named it would have tied with `typescript` everywhere. `typescript` now
selects on `tsconfig.json`, `vite.config.{ts,js}` and `vitest.config.{ts,js}`.
Measured on five real repositories: a Vue app on Vite selects `typescript`, a
React Native app on Jest selects `jest`, an Astro site selects `typescript`, and
two Laravel apps carrying a Vite config stay on `laravel-pest`. A repository
holding a `package.json` and nothing else now selects no profile; v0.8 selected
`typescript` there. `cr init` updates an unedited v0.8.0 `typescript.json`.

## `npx` no longer reads the runner's flags

`npx` takes `--verbose`, `--json` and `--version` as npm's own flags, so
`npx --no jest --json` printed npm's log and never reached Jest. Both JavaScript
profiles now run `npx --no -- <runner>`, which hands everything after `--` to
the runner.

## A zero is read only from a clean exit

A Jest suite that throws on import reports zero passed and zero failed and exits
1. The sum mode read that as a run of zero tests, and a mutation probe would
have answered `no-tests-selected` — "your filter matched nothing" — about a
mutation that broke loading. The occurrence mode already read a zero only from
an exit of 0; §5.2.1 now applies that rule to both modes, and such a run is
undetermined. No shipped profile read a zero differently before: Pest prints no
recap when it runs nothing.

## Also in this release

- Mutation testing over the v0.8 code found two test gaps and closed them. A line
  naming two head symbols reported only the first, and a Rust lifetime ending its
  line, as in `where T: 'a`, was never exercised; its mutant panicked.
- When the stopped-probe test that failed once in September fails again, it now
  prints the runner group's processes and the load averages.

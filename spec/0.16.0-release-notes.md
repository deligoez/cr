# cr v0.16.0 — Fewer prompts, nothing lost, less to edit

> The release notes for the `v0.16.0` tag.

cr's first measured run on a real pull request on a private Laravel repository spent about 480
thousand tokens on 52 prompts, of which some 15 carried meaning. It lost the one observation that
pointed outside the diff, and it left English in a Turkish comment. v0.16.0 settles §4.6, §7.3,
§8.1.7 and §10.4; the contract is `spec/0.16.0.md`.

## Install

```bash
brew install deligoez/tap/cr
go install github.com/deligoez/cr/cmd/cr@v0.16.0
```

## A unit's kind decides which roles read it (§2.4, §4.6.7)

Many of those 52 prompts asked a correctness, convention or test role to read a changelog entry or
a translated string. A profile can now declare unit kinds in `units.kinds`, each as
`{kind, globs, roles}`. When every path of a unit matches a kind's globs, the unit is of that kind.
`cr review` then emits prompts only for the roles the kind lists. For every other active role, cr
records the cell itself as `na`, with a reason naming the kind, through the same writer as
`cr cells record`. `expected_cells` reports those cells `recorded`, and `cr status` and `cr next`
count the row like any other. `--all` does not bring the withheld prompts back.

`laravel-pest` declares two kinds:

- `changelog` over `changelogs/**`
- `translation` over `resources/lang/**` and `lang/**`

Each lists `intent-coverage` alone.

## A unit that repeats another's change is read once (§4.6.8)

Two event-test files received the identical change, and every role read both (`u9` and `u11`,
`u10` and `u12`). When a unit's hunks match an earlier unit's line for line after §1.4's
normalisation, it is now that unit's **twin**. The hunk headers are left out of the comparison,
because they say where the change sits and not what it is.

- `cr brief` records the pairing as `twin_of` on the unit and prints
  `twin of u9 per §4.6.8` on its line.
- `cr review` emits no prompt for a twin. The earlier unit's prompts list its twins under
  *Twins of this unit*.
- Whenever a cell of the earlier unit is recorded, cr records the same `result` at the twin's seat,
  with the twin's own unit hash and a reason naming the earlier unit. `cr cells record` reports
  these cells under `twinned`. A twin seat that the file names itself keeps the file's cell.
- A record or a claim mapping that holds for a twin is still the role's to write.

## What a role saw outside its unit is kept (§4.6.9)

On the same pull request, a role noticed that the `locale:` defect the change fixed in one directory
was still present in a file in a sibling directory, outside the diff. A record has to be anchored
inside a unit, so the role had nowhere to put it.

Every prompt now names `fanout/<round>/<unit>/observations-<role>.ndjson`, and `contract.md` carries
the schema `{path, line, text}`. `line` is optional for a file as a whole.
`cr observations record <pr> <file>` stores the lines in the new `observations.ndjson`, with the
round and head. It rejects the whole file with exit code 1 if a line is missing `path` or `text`,
has a `path:line` that does not resolve at the head, or carries any other key.

An observation is not a record. It is never graded, posted or counted. `cr status` lists every
observation of the round under `observations`, and `cr draft` shows them in the header it owns,
which nothing posts. `cr next`'s `record` step names every observations file written after the
round's last `cr observations record` (§10.4.5).

## The evidence region speaks `render.lang` (§8.1.7)

The region beneath a probed or cited comment named its fields in English whatever the review's
language: under `render.lang tr`, an otherwise Turkish comment still read `kind:`, `target:`,
`paths:`, `result: no-test-failed`, `input:` and `output_tail, the lines tests.count_pattern
matches:`. The field names are now built in per language, as the question labels and the review
body's framing already were, and are not configurable. Under `tr` they read `tür`, `hedef`,
`filtre`, `yollar`, `sonuç`, `girdi`, `test çıktısı`, `test çıktısı (özet)`, `kaynak` and
`yeniden koşu`; a truncated input says so in Turkish, and a gap probe's §5.4.4 limit is a Turkish
`sınır:` row. The values beneath the names — a probe's kind, target and `result` — are cr's
vocabulary and are written as the record holds them. English output is byte for byte what it was.

## `cr stats` counts the comments posted unedited (§7.3.2)

A `kept` or `softened` event in `triage.ndjson` now carries `edited`: `true` when the body posted
differs from the body the round's last `cr draft` wrote into `draft.md`, `false` when it does not.
That reference includes an agent's rewrite in `render.lang` the draft preserved, so in the
ordinary flow — the agent rewrites, runs `cr draft`, the human reads and sends — only a change made
after that last `cr draft` counts as an edit. `cr draft` keeps the bodies it wrote in the round's
`summary.json` under `drafted_bodies`. `cr stats` reports two new counts per class and per rule:
`unedited`, and `edit_unknown` for events that carry no mark, such as those an earlier release
wrote; counting an unmeasured event as unedited would report blocks as sendable that nobody
measured. The count answers one question: can a human send every block without editing it?

## `cr next` proposes no post to a pull request that is no longer open (§10.4.8)

When the round's last `cr brief` found the pull request merged or closed, the `draft` step still
lists `cr draft`, so the draft stays readable, but it says so and no longer lists `cr post`.

## Upgrading

`cr init` updates a `laravel-pest.json` that is still byte-equal to the one an earlier release
shipped. Until then, every command that loads it reports that the shipped profile has since
changed `units`. A state directory created before v0.16.0 gets `observations.ndjson` the next time
`cr brief` runs. Until then, `cr status` and `cr draft` read the missing file as holding no
observation.

# cr v0.6.2 — What the run measured, in the run's own output

> The release notes for the `v0.6.2` tag.

v0.6.1 shipped the two defects the v0.6.0 QA pass found that a reader could be misled by. v0.6.2 is
the rest of what that pass left: five smalls, none of which could put a wrong assertion in front of
an author, and one measurement that had never been made. The contract is still `spec/0.6.0.md`, and
none of this changes a word of it.

## Install

```bash
brew install deligoez/tap/cr
go install github.com/deligoez/cr/cmd/cr@v0.6.2
```

## `cr test` prints the counts it stored

v0.6.0 shipped the `go` profile with an occurrence count mode — a runner that prints one line per
test, and a zero read only from a clean exit. The way an operator checks that against their own
suite is to run `cr test`, and its output carried no counts at all: `tests_run`, `tests_failed` and
§5.2.5's `passed` reached `runs.ndjson` under `~/.cr` and nowhere a reader looks.

They are in the command's output now, and left out rather than zeroed when the profile's patterns
derive neither — a count nobody measured is not a zero.

```json
{"run": "r3", "exit_code": 1, "tests_run": 3, "tests_failed": 1, "passed": false, …}
```

## A brief says when GitHub is still reporting the old head

Measured during the QA: a `cr brief` run straight after a push stayed in the old round, because
GitHub's API still answered the pre-push head for a few seconds; the next brief opened the new
round. Nothing in the output said so, and the cost is a whole fan-out against the wrong head. (No
comment could go wrong: §9.3.2 refuses every per-PR write while the heads differ.)

`cr brief` now reads the remote's `refs/pull/<pr>/head` beside gh's answer — one `git ls-remote`,
which writes nothing, not even a ref of the clone — and discloses both commits when they disagree,
so the operator can compare them with what was pushed. It is a disclosure and not a refusal:
refusing would be a new exit-4 condition, which the spec does not have.

## Three refusals that named no step

- **A head that shares no history with its base.** `git merge-base` answers that with exit 1 and an
  empty stderr, so cr surfaced `exit status 1` and no step — against its own rule that every error
  names the next one. It is now its own error, and the hint says the head was not branched from the
  base.
- **`cr config --resolved` under the GitHub tracker.** It listed the Jira key pattern and the tracker
  command as if they held, while §3.2 holds keys to `owner.repo#n` and §3.1.8 starts no `intent.cmd`.
  Both rows stay, because §2.7 annotates every setting; each now says it is not in force and why. A
  resolved view that quietly lists an inert value is the one thing it must not do.
- **A pull request that closes two issues.** The refusal was right — which issue the change is
  reviewed against is the reviewer's to say — and its hint named neither candidate. The error had
  carried a hint that did name one, and nothing read it; the hint is now read, and names every
  candidate as the flag to pass.

## `cr post --reconcile`, measured against a real lost answer

§8.4's unknown outcome had been exercised only through the unit suite's shim. Measured 2026-09-22 on
`deligoez/cr-qa#21`: a `gh` on `PATH` forwarded the review POST to the real gh and then reported the
answer lost, so GitHub held review 5282249926 and cr knew nothing about it. `cr post --confirm`
exited 4 and set `post_unresolved`. `cr post --reconcile`, with the real gh, matched §8.4.3's payload
hash `807bf9e0aa6cd139` against the pull request's reviews, adopted that one, moved the record to
`posted` with its thread, and cleared `post_unresolved`; the next `cr post` was refused as an
already-posted round. No code changed for this; what changed is that it is no longer an untested
claim.

## Upgrading

Nothing to do. No state format changed and no command gained or lost a flag. `cr brief` now makes
one extra network read, a `git ls-remote` against the remote that points at the pull request's
repository; when the clone has no such remote, or the read fails, the brief is exactly what it was.

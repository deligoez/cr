# cr v0.7.0 — A push carries the draft

> The release notes for the `v0.7.0` tag.

Until v0.6, an author's push threw away every comment you had drafted and not yet sent. `cr brief`
opened the new round and moved each `draft` and `queued` record to `stale`, including the ones
whose code had only moved a few lines and whose body you had already rewritten. v0.7 carries them.

It also settles a contradiction in the spec. §9.4 described migrating those records' anchors across
a push, and §9.3.4 staled them on the same push, so nothing a migration found was ever kept. The
v0.6.0 QA pass found this; the user chose to make the migration matter rather than strike it.
`spec/0.7.0.md` is the contract.

## Install

```bash
brew install deligoez/tap/cr
go install github.com/deligoez/cr/cmd/cr@v0.7.0
```

## What a push does now

On the brief that opens a new round, every unsent record is migrated to the new head. cr looks for
its anchored lines by their content hash, first in the record's own file and then in every file the
new diff touches, and widens to the recorded context window when there are several matches.
A record is **carried** when its anchor is RIGHT, is found in exactly one place, and that place lies
inside a unit of the new round, so a comment can still be posted there. A carried record keeps its
id, moves to the new round, the new line and the unit that contains it, and goes back to `draft`,
because you approved it at the old place. Everything else goes `stale` as before: a LEFT anchor,
code that is gone, code that is now in two places, or a line the new diff no longer covers.

```json
{"round": 3, "carried_records": ["f3", "f4", "f301"], "staled_records": [],
 "migrations": [{"record": "f301", "from": "src/Order.php:28", "to": "src/Order.php:30",
                 "placed": true, "carried": true, "from_round": 2, …}]}
```

That brief is from a pull request on a scratch QA repository. Two comment lines were pushed above
three queued records, all three were carried two lines down, and the round's first `cr draft`
rendered `f301` at lines 29–30 with the body the reviewer had written, not a fresh one.

## A carried comment asserts nothing it proved at the old head

This is the part the trust economy asks for. A comment that moves also moves away from the evidence
it was graded on, so the carry re-reads that evidence:

- **The probe is cleared.** It ran against code the push changed. The migration line names the
  probe, so you can run it again at the new head.
- **A citation whose line changed loses its stamp.** cr stamps each citation with the hash of the
  line it names; a carried record keeps the stamp only where the line still holds that content.
  An unstamped citation no longer counts towards `cited`.
- **The grade is computed again at the carry**, over what is left, and can only fall.

The last one matters because `cr draft` regrades only the records a triage moved, and leaves the
full recomputation to `cr post`. Without it, the draft would have shown you a carried record still
`probed` and still a finding, over evidence the carry had just cleared. So a carried `probed`
finding falls to `cited` or `argued` before you read it, and an `argued` one is a question again
until you re-run the experiment.

## Two counts the carry would otherwise have made wrong

- **A record is raised once per pull request.** Triage statistics key a raise by round, so a
  carried record would have been raised twice and would have counted twice in a class's demotion
  rate. `cr draft` no longer raises a record the pull request has already raised.
- **A re-raise is a duplicate.** The new round's roles review the carried record's unit again, and
  may raise the same concern at the same line and class. `cr record` now stores that as a duplicate
  of the record the round already holds, and keeps the held one, whose body you may have edited.
  Before this, the draft would have carried two comments on one line.

## `cr recheck`

With the heads agreeing, `migrated` reports what the brief wrote to `migrations.ndjson` for this
round, each line marked carried or staled. While the head has moved past the round and no brief has
run, `preview` says what the next brief would place, searching the same files the brief searches,
and nothing is written. v0.6's recheck searched only the anchor's own file, so code moved into
another file always read as gone.

## Upgrading

Nothing to do. Records written by earlier versions are migrated like any others on the next push.
`cr recheck`'s JSON gains `preview`, and `migrated` now holds the brief's records rather than a
computation.
